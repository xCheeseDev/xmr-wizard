Test your connection

Every time you open the Node Map or Node List, every node gets pinged fresh from your browser and ranked by speed.

Open the Node Map or Node List tab to test your connection — fresh ping every time.

Pick a node

The dropdown ranks nodes fastest healthy first. Ping is the median of 3 probes from your browser to the node's RPC port (6s timeout each). Health comes from an hourly automated check of each node's block height — it can't be faked by a fast connection. Onion nodes only work in Tor Browser; in a normal browser they'll show as timeout.

Test a custom node

Heard about a node that's not on the list? Check it directly.

How it works

  • Measured from you. Latency is probed from your own browser, because a node that's fast for someone else might be slow for you. Nothing is uploaded anywhere — the test traffic goes straight from your device to each node.
  • Speed + health. A fast ping alone doesn't prove a node is usable, so an hourly automated check records every node's block height and version into status.json. Nodes that are offline or far behind the chain are pushed to the bottom.
  • No backend. This page is static. The node list is a nodes.json file in the repo that anyone can improve with a pull request.
  • Honest limits. Browsers block normal requests to node RPC ports, so the probe uses a timing trick (see README). The health data is only as fresh as the last hourly check. A synced node you connect to still sees your IP — the privacy note below applies.

A privacy note

A remote node can see your IP address and when you broadcast transactions. If that bothers you, use one of the Tor onion nodes (in Tor Browser) — or better yet, run your own node. Your keys never touch this page either way.
